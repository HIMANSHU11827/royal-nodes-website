# User Taste
- Treats any dead or shared click target as a bug: every menu/nav item and CTA must land on its own correct, dedicated destination (not a single generic page), and the fix must be verified in a real browser rather than declared done. Confidence: 0.6
- Wants motion everywhere and in quantity, not just on the landing page — scroll reveals, hover/tilt effects, animated backgrounds/panels are a baseline site-wide expectation rather than a one-off flourish, and asks for "tons" of graphics/animation layers (aurora, particles, streams, shapes, constellation, grain) rather than a single subtle effect. Confidence: 0.9
- Rejects "generic trash" presentation: thin two-to-three-word labels and template copy are unacceptable; each page should carry substantial, page-specific written content ("tons of info"). Confidence: 0.7
- Expects written content to be grounded in the actual product: before drafting pages like Terms & Conditions, read the existing site and match how the business really works rather than pasting generic boilerplate ("read website, understand, make proper"). Confidence: 0.65
- Expects every new page/feature to be discoverable from the main top navigation — burying it in the footer or mobile menu triggers "where is it?" and gets a correction. Confidence: 0.5
- Prefers short, plain-language answers — asks for "simply" when responses get long and detailed; lead with the bottom line. Confidence: 0.7
- In research/analysis discussions, wants explanation only — no code, no writing files; "don't code, just tell me" is a standing instruction, not a one-off. Confidence: 0.7
- Wants every product to follow a three-tier plan structure (cheap / budget / premium) with several plans per tier (~6), rather than a flat single-price listing — and a "tier" must be a real power stage where power and price scale up across tiers (low-power = cheaper). Confidence: 0.7
- Tiers and plans must be admin-managed data, not hardcoded: the admin adds/removes tiers, names tiers freely (not locked to Cheap/Budget/Premium), sets any number of tiers (two, three, or more — never fixed at exactly three), and adds/removes the plans nested inside each tier. Confidence: 0.65
- Customer-facing pages must not expose hardware jargon (CPU, RAM, DDR4/DDR5, cores, NVMe) or any plan descriptions / "ideal for" copy because most buyers won't understand it — show only the tier name (Cheap / Budget / Premium), the plan name, and the price. Confidence: 0.85
- Treats every customer-facing content item (deals, promotions, seeded demo entries) as admin-managed data: the admin must be able to give it a custom name and freely change, add and remove it inline, with edits persisting — seeded/read-only content counts as "not working". This includes every field of the record, not just name/price: what product and plan an item is attached to must be selectable and editable in the admin too, or the feature is reported as incomplete ("what product given, you did not do that"). Confidence: 0.8
- Wants strict least-privilege role separation in the admin panel: staff accounts get only the minimal operational views/actions, while dashboards, provisioning-type features and financially destructive actions (refund, cancel) stay admin-only. Confidence: 0.6
- Expects an admin panel to be wired end-to-end to the live site and to cover the full product lifecycle (purchase → expiry → renewal, coupon validity windows, user-selectable locations/options) rather than mock or partial controls; flags anything non-functional as "many things missing/not working". Confidence: 0.6
- Prefers direct, implicit interactions over explicit action buttons: a table row should be clickable to expand its drill-down detail (toggle open/closed) instead of needing a separate View/Hide button. Confidence: 0.6
